分类 1stdio.h 输入输出

stdio.h 是 C 程序与外界交流的总入口:格式化打印、键盘输入、文件读写全在这里。它的核心抽象是带缓冲的流(FILE *)——标准流 stdin/stdout/stderr 程序启动即可用,磁盘文件则由 fopen 打开、fclose 关闭。本章按"格式化 I/O → 文件打开关闭 → 块与行读写 → 定位与缓冲 → 错误处理"的顺序展开;历史遗留的不安全函数(gets、无宽度的 %s、sprintf)会逐一标注替代方案。

速览

本章速览——stdio.h 把"格式化"与"流"两件事捏在一起，先记住每个函数的返回值含义，一半的坑就绕过去了。

函数一句话说明备注
printf按格式把数据写到标准输出格式串与实参类型必须严格对应，否则是未定义行为；永远不要把变量直接当格式串传入
fprintf按格式写入指定的文件流目标流须以写或追加模式打开；诊断信息写 stderr，可绕开 stdout 的缓冲延迟
sprintf / snprintf按格式写入字符串缓冲区sprintf 不限长度，溢出即踩内存 禁用；一律用 snprintf 推荐，但它返回的是"本应写入的长度"，可能大于缓冲区
sscanf从字符串中按格式解析数据%s 不加宽度必然溢出，写成 %49s；判断成功与否要看返回的匹配项个数，而不是看变量
scanf从标准输入按格式读取会把换行留在输入缓冲里，和 fgets 混用即出错；交互式输入改用 fgets + sscanf 推荐
fopen / fopen_s打开文件并返回流指针返回值必须判空再用；处理非文本数据要加 "b"，否则 Windows 会改写换行符。fopen_s 属 C11 可选附录，跨平台不保证存在
fclose关闭流并刷新其缓冲区忘记关闭可能丢掉尾部数据；返回值能暴露最后一次写入失败，别一律忽略
fread从流中读入若干个定长块返回的是成功读取的"块数"而非字节数；数量不足时须用 feof / ferror 区分读完与出错
fwrite把内存中的数据块写入流直接整体写结构体不可移植，对齐填充和字节序都会变；返回块数同样要校验
fgets读入一行，长度受缓冲区限制安全但会把 '\n' 一并留下，通常需手动截断；它的前辈 gets 已从标准中删除 禁用
fputs把字符串原样写入流不会自动补换行，这一点和 puts 相反，最常见的"输出粘一行"就源于此
fgetc / fputc逐个字符地读入与写出fgetc 返回 int 不是 char；用 char 变量接收会把 0xFF 误判成 EOF
fseek / ftell / rewind定位、查询与重置读写位置文本模式下的偏移量只能原样回传，不能做加减；超 2GB 文件需 fseeko 或 _fseeki64。rewind 会顺手清掉错误标志
fflush强制把缓冲中的数据写出仅对输出流有定义，fflush(stdin) 是未定义行为 禁用，清输入请循环读到换行
feof / ferror查询流的结束标志与错误标志feof 要读失败之后才为真，拿它当循环条件会多处理一次数据；正确写法是判断读取函数本身的返回值
remove / rename删除文件、重命名或移动文件目标已存在时的行为由实现决定，可能失败也可能覆盖；操作不可撤销，动手前先确认路径
perror按 errno 打印带前缀的错误信息必须紧接在失败调用之后使用，中间插入任何库调用都可能改写 errno
setvbuf设置流的缓冲方式与缓冲区大小只能在打开之后、任何 I/O 之前调用；若自备缓冲区，其生命周期必须长于该流

printf

按格式串把变量拼接成文本写到标准输出，是最常用的屏幕打印函数。

函数原型

int printf(const char *format, ...);

参数

参数类型说明
formatconst char *格式串,决定后续可变参数如何被解释并写往 stdout。必须是程序自己写死的字面串;把外部输入当格式串传入即格式串漏洞。占位符与实参类型的对应关系见下方"其他说明"中的占位符表
...可变参数与格式串中的占位符一一对应的实参。个数或类型不匹配都是未定义行为;float 会自动提升为 double,char/short 提升为 int,指针需显式转成 (void *) 才配 %p

返回值

成功返回实际写出的字符总数(不含结尾的 \0);失败返回负值。出错详情可用 ferror(stdout) 判断流的错误标志,并结合 errno / perror 取具体原因。

示例

int n = -7;printf("n=%d sz=%zu\n", n, sizeof n);// n=-7 sz=4printf("%08.3f | %x | %c\n", 3.14159, 255, 'A');// 0003.142 | ff | Aprintf("%p\n", (void *)&n);// 打印指针要转 void*printf("%-10s|%.3s|\n", "hello", "hello");// 左对齐宽 10;截断成 hel

其他说明

常用占位符与实参类型的对应关系:

占位符对应实参类型说明
%d / %iint十进制有符号整数
%uunsigned int十进制无符号整数
%ld / %lldlong / long long长整数;无符号对应 %lu / %llu
%zusize_tsizeof、strlen 结果的专用占位符(C99)
%fdouble定点小数;%.2f 控制精度(float 实参自动提升为 double)
%e / %gdouble科学计数法 / 自动选较短形式
%x / %Xunsigned int十六进制小写 / 大写;%o 为八进制
%cint(按字符输出)单个字符
%schar *以 \0 结尾的字符串;%10s 定宽、%.5s 截断

%%—输出百分号本身
禁用写法

格式串与实参类型不匹配是未定义行为(如用 %d 打印 long long)。更危险的是把外部输入直接当格式串:printf(user_input) 是经典的格式串漏洞,必须写成 printf("%s", user_input)。

现代提示

C++ 中优先用类型安全的 std::format(C++20)/std::print(C++23),占位符写错在编译期即可发现。

fprintf

和 printf 一样做格式化输出，但可以指定写到哪个流，写日志、往 stderr 报错都靠它。

函数原型

int fprintf(FILE *stream, const char *format, ...);

参数

参数类型说明
streamFILE *目标流:stderr、stdout 或 fopen 打开的文件流。必须以写或追加模式打开;诊断信息应写 stderr
formatconst char *格式串,占位符规则与 printf 完全相同。同样不得使用外部输入作为格式串
...可变参数与格式串占位符一一对应的实参,类型必须严格匹配

返回值

成功返回写出的字符数;失败返回负值。失败详情用 ferror(stream) 判断,并配合 errno / perror 查看原因。

示例

fprintf(stderr, "error: cannot open %s\n", path);// 错误信息走 stderr,不受重定向干扰FILE *log = fopen("app.log", "a");if (log) fprintf(log, "[%d] started\n", pid);// 写日志文件

其他说明

printf(...) 等价于 fprintf(stdout, ...)。stderr 默认无缓冲(或行缓冲),诊断信息应写这里而不是 stdout,否则程序异常终止时缓冲中的提示可能根本没来得及输出。

sprintf / snprintf

把格式化结果写进内存里的字符串而不是屏幕；snprintf 多一个容量上限，sprintf 毫无防护、极易写爆缓冲区。

函数原型

int sprintf(char *buf, const char *format, ...);
int snprintf(char *buf, size_t n, const char *format, ...);

参数

参数类型说明
bufchar *接收结果的目标缓冲区。sprintf 无长度上限,写爆缓冲区没有任何防护,直接造成栈/堆溢出
nsize_t仅 snprintf 有:缓冲区总容量。最多写入 n-1 个字符并保证补 \0(C99);传 0 时不写入任何内容,此时 buf 可为 NULL,常用来先探测所需长度
formatconst char *格式串,占位符规则同 printf
...可变参数与占位符一一对应的实参

返回值

两者都返回"完整输出本应占用的字符数"(不含 \0);编码错误时返回负值。对 snprintf,返回值 >= n 即说明发生了截断,应据此扩容重试;先调用 snprintf(NULL, 0, ...) 可探测所需长度再分配。

示例

char buf[32];
int need = snprintf(buf, sizeof buf, "id=%d name=%s", 42, name);
if (need < 0) { /* 编码错误 */ }
else if ((size_t)need >= sizeof buf) { /* 被截断,按需扩容重试 */ }

其他说明

已过时 sprintf 不知道目标缓冲区多大,输出一旦超长即栈/堆溢出。推荐 snprintf 用 n 封顶且必定以 \0 结尾,是格式化到缓冲区的唯一正确选择。

现代提示

MSVC 对 sprintf 报 C4996 弃用警告,并提供 sprintf_s(越界时直接终止而非静默截断)。C++ 里直接用 std::string + std::format,缓冲区大小问题整个消失。

sscanf

从一段字符串里按格式抠出数字、单词等字段，常配合 fgets 用来逐行解析文本。

函数原型

int sscanf(const char *src, const char *format, ...);

参数

参数类型说明
srcconst char *被解析的源字符串(而非流),须以 \0 结尾。常见用法是先用 fgets 读一整行再交给它解析
formatconst char *格式串。%s、%[ 等字符串类占位符必须带宽度,且宽度要比数组容量小 1(留给 \0),如 %19s 配 char word[20];格式串中的空白可匹配任意个空白字符
...可变参数接收结果的变量地址(&y、数组名等),忘记取地址是最常见的崩溃原因;类型必须与占位符严格对应

返回值

成功返回实际匹配并完成赋值的项数;在第一项匹配成功之前就到达串尾或失败,返回 EOF。务必比较返回值与期望项数,否则失败时接收变量仍是未初始化值。sscanf 不设置有意义的 errno,需要精确的错误定位应改用 strtol / strtod 并检查其 endptr 与 errno。

示例

int y, m, d;
if (sscanf("2026-08-14", "%d-%d-%d", &y, &m, &d) == 3) {
    // 三项全部解析成功才可使用
}
char word[20];
sscanf(line, "%19s", word);   // %s 必须带宽度,且比数组小 1(留给 \0)

其他说明

"fgets 读一行 + sscanf 解析"是替代 scanf 的标准安全套路:行边界由 fgets 控制,解析失败也不会污染输入流。需要精确错误定位的数值解析用 strtol/strtod 更好。

scanf

直接从键盘输入按格式读取数据，写起来省事，但残留换行和缓冲区溢出的坑特别多。

函数原型

int scanf(const char *format, ...);

参数

参数类型说明
formatconst char *格式串,从 stdin 按此解析。%s 不带宽度必然溢出,必须写成 %15s 之类;%d、%s 不消耗行尾换行,残留的 \n 会被后续 fgets/%c 读到
...可变参数接收变量的地址(数组名本身即地址,故 %s 传 name 而非 &name)

返回值

成功返回完成赋值的项数;在任何赋值发生前输入耗尽或读取出错则返回 EOF。返回值小于期望项数说明匹配失败,此时非法输入仍滞留在 stdin 中,必须循环 fgetc 读到 \n 或 EOF 清干净;读取错误可用 ferror(stdin) 与 errno 进一步区分。

示例

char name[16];
int age;
if (scanf("%15s %d", name, &age) != 2) {   // %s 带宽度 + 检查返回值,缺一不可
    // 输入不合法:坏数据仍留在 stdin 里,需读丢
}

其他说明

为何易出事

三大坑:① 无宽度的 %s 读多长写多长,直接缓冲区溢出;② 匹配失败时非法输入滞留在缓冲区,循环里不清理就是死循环;③ %d、%s 不消耗行尾换行,后续 fgets/%c 会读到残留的 \n。交互式输入优先改用 fgets + sscanf。

MSVC 对 scanf 报 C4996,其 scanf_s(C11 附录 K)要求 %s/%c 后额外传缓冲区大小实参,如 scanf_s("%s", name, (rsize_t)sizeof name);该扩展可移植性有限。C++ 等价物是 std::cin >> x 配合状态检查。

fopen / fopen_s

按指定模式打开文件并拿到流指针，是后续一切文件读写的起点；fopen_s 改用参数传出流、返回错误码。

函数原型

FILE *fopen(const char *filename, const char *mode);
errno_t fopen_s(FILE **fp, const char *filename, const char *mode);

参数

参数类型说明
fpFILE **仅 fopen_s(C11 附录 K / MSVC)有:用于传出流指针的二级指针,函数成功时把打开的流写入 *fp
filenameconst char *文件路径,可为相对路径或绝对路径。Windows 上反斜杠在字符串字面量中要写成 \\
modeconst char *打开模式串,取值见下方"其他说明"的模式表。处理非文本数据必须加 b(如 "rb"),否则 Windows 会自动转换 \n 与 \r\n 而破坏数据

返回值

fopen 成功返回可用的流指针,失败返回 NULL 并设置 errno——返回值必须判空再用,失败原因用 perror / strerror(errno) 打印。fopen_s 成功返回 0,失败返回非零的 errno_t 错误码,流本身经第一个参数传出。

示例

FILE *fp = fopen("data.bin", "rb");// 二进制数据必须带 bif (!fp) {    perror("fopen");// 打印失败原因    return 1;}

其他说明

mode 的常用取值:

模式含义文件不存在时
"r"只读失败,返回 NULL
"w"只写,清空原内容新建
"a"追加,写入总发生在文件末尾新建
"r+" / "w+" / "a+"加 + 表示可读可写(基础语义不变)同各自基础模式
b 后缀二进制模式,如 "rb"、"wb+";Windows 上关闭 \n 与 \r\n 的自动转换—

MSVC 下 fopen 触发 C4996,可换 fopen_s 或定义 _CRT_SECURE_NO_WARNINGS;fopen_s 属 C11 可选附录,跨平台不保证存在。C++ 等价物为 std::ifstream/std::ofstream(RAII 自动关闭)。

fclose

关闭文件流，顺带把缓冲区里还没写出去的数据刷到磁盘，漏掉它就可能丢数据。

函数原型

int fclose(FILE *stream);

参数

参数类型说明
streamFILE *要关闭的流。函数会先刷新其缓冲区、再关闭文件并释放 FILE 资源。对同一指针重复调用是未定义行为;传入 NULL 同样是未定义行为

返回值

成功返回 0;失败返回 EOF 并设置 errno(可用 perror 打印)。写文件时这个返回值必须检查——最后一批缓冲数据可能到此刻才真正落盘,磁盘满、配额超限等错误只有在这里才暴露。

示例

if (fclose(fp) == EOF) {    perror("fclose");// 落盘失败:数据可能不完整}fp = NULL;// 防止悬空指针被再次使用

其他说明

对同一指针重复 fclose 是未定义行为;关闭后置 NULL 是廉价的保险。

fread

从流里按「元素大小 × 个数」成块读入内存，是读二进制文件的主力函数。

函数原型

size_t fread(void *ptr, size_t size, size_t count, FILE *stream);

参数

参数类型说明
ptrvoid *目标缓冲区,容量必须至少为 size * count 字节
sizesize_t单个元素的字节数,通常写 sizeof(T)
countsize_t想读入的元素个数;实际读到的个数由返回值给出,不能假定一定读满
streamFILE *已打开的输入流,读二进制数据时通常以 "rb" 打开

返回值

成功返回实际读到的完整元素个数(不是字节数),等于 count 表示全部读满。小于 count 时不能直接判定为失败:用 feof(stream) 说明正常读到文件尾,ferror(stream) 为真才是真出错,详情再看 errno / perror。

示例

int nums[100];
size_t got = fread(nums, sizeof(int), 100, fp);
if (got < 100 && ferror(fp)) {
    perror("fread");          // 真错误,而非正常读到末尾
}

fwrite

把内存里的一块数据按元素成块写进流，是把数据原样存盘的主力函数。

函数原型

size_t fwrite(const void *ptr, size_t size, size_t count, FILE *stream);

参数

参数类型说明
ptrconst void *数据来源,需保证从该地址起有 size * count 字节可读
sizesize_t单个元素的字节数
countsize_t要写出的元素个数
streamFILE *已打开的输出流,写二进制数据时通常以 "wb" 打开

返回值

成功返回写入的完整元素个数;小于 count 即出错,用 ferror(stream) 确认并以 perror / errno 取具体原因。注意数据此时未必落盘,真正的写入错误也可能推迟到 fflush 或 fclose 才报出。

示例

double table[256] = {0};
if (fwrite(table, sizeof table[0], 256, fp) != 256) {
    perror("fwrite");
}

其他说明

直接落盘结构体会把填充字节和本机字节序一并写进文件,跨平台读取会出问题;需要可移植格式时应逐字段序列化。

fgets

从流里读一整行文本到定长缓冲区，读多少受容量限制，是已被删除的 gets 的安全替代品。

函数原型

char *fgets(char *buf, int n, FILE *stream);

参数

参数类型说明
bufchar *目标缓冲区。结果一定以 \0 结尾,行尾的 \n 会被保留,通常需用 buf[strcspn(buf, "\n")] = '\0' 截掉
nint缓冲区总大小(含 \0),最多读入 n-1 个字符。直接写 sizeof buf 最稳妥;若整行超过 n-1,余下部分会留在流中由下次调用继续读
streamFILE *输入流,交互场景传 stdin

返回值

成功返回 buf(即传入的指针);到达文件尾且一个字符都没读到、或读取出错时返回 NULL。两种情况需用 feof(stream) / ferror(stream) 区分,出错详情再查 errno。

示例

char line[256];
while (fgets(line, sizeof line, fp)) {
    line[strcspn(line, "\n")] = '\0';   // 一行代码去掉结尾换行
    process(line);
}

其他说明

推荐 读取一行文本的首选函数:长度受缓冲区限制,不会溢出。

禁用

返回值

成功返回 0;失败返回 EOF 并设置 errno,同时置位该流的错误标志,可用 ferror(stream) 与 perror 取详情。

printf("processing...");// 没有 \n,行缓冲下不会立刻显示fflush(stdout);// 强制刷出,进度提示即时可见

feof / ferror

读写失败之后查流的两个状态标志，用来区分是正常读到文件尾还是中途发生了 I/O 错误。

函数原型

int feof(FILE *stream);
int ferror(FILE *stream);

参数

参数类型说明
streamFILE *被查询的流。feof 查它的文件尾标志——即"上一次读取是否因到达文件尾而失败";ferror 查它的错误标志——即流上是否发生过 I/O 错误。两个标志都用 clearerr(stream) 一并清除,rewind 也会顺手清掉

返回值

相应标志被置位时返回非零,否则返回 0;两者本身都不会失败,也不设置 errno。关键语义:feof 只有在一次读取已经失败之后才为真,它不能预告"下一次读会不会到头",所以绝不能拿它当循环条件。具体的错误原因要靠 ferror 为真后再查 errno / perror。

示例

while (!feof(fp)) {// 错:最后会多循环一轮,末条数据被处理两次    fgets(buf, sizeof buf, fp);    process(buf);}while (fgets(buf, sizeof buf, fp)) {// 对:用读取函数的返回值控制循环    process(buf);}

其他说明

循环正常结束后,用 ferror(fp) 区分"读完了"和"读坏了";clearerr(fp) 可同时清除两个标志。

newnameconst char *仅 rename 有:新路径,可用于重命名或在同一文件系统内移动。目标已存在时的行为由实现决定(POSIX 原子覆盖,Windows 直接失败);跨盘符/跨文件系统移动通常也会失败

返回值

成功返回 0;失败返回非零并设置 errno,原因用 perror / strerror(errno) 打印(常见如目标被占用、权限不足、跨盘符移动)。

    perror("rename");         // 例如目标被占用、跨盘符移动

其他说明

目标文件已存在时,POSIX 的 rename 原子覆盖,Windows 则直接失败——跨平台代码不能依赖覆盖语义。删除已被打开的文件在 Windows 上通常也会失败。

perror

取当前 errno 配上你给的前缀，向 stderr 打印一行人类可读的失败原因。

参数

参数类型说明

无返回值,失败与否也无从判断。它读取的是调用时刻的全局 errno,因此必须紧接在确认失败的调用之后使用——中间插入任何库调用都可能改写 errno。

FILE *fp = fopen("cfg.ini", "r");

}

malloc

在堆上要一块指定字节数的内存,内容是垃圾值,用完必须自己 free 归还。

函数原型

void *malloc(size_t size);

参数

参数类型说明
sizesize_t要分配的字节数。惯用写法是 n * sizeof *p,这样改变元素类型时这行代码不用跟着改。分配得到的内存未初始化,内容是垃圾值,必须先写后读。size 传 0 时行为由实现定义

返回值

成功返回指向已分配内存的指针(对齐满足任何基本类型的要求);失败返回 NULL,因此返回值必须判空后才能使用。malloc(0) 的返回值由实现定义,可能是 NULL,也可能是一个可以传给 free 的非空指针,但两种情况下都不得解引用。C 标准没有规定失败时设置 errno;POSIX 平台通常会置为 ENOMEM,可在失败分支用 perror/strerror(errno) 取错误详情,但不要把它当作可移植的判断依据——判空才是唯一可靠的失败检测手段。

示例

int *p = malloc(100 * sizeof *p);// sizeof *p:改类型时这行不用动if (p == NULL) {    // 分配失败:报错并返回,不要硬着头皮往下走    return -1;}p[0] = 42;// 内容是垃圾值,读之前必须先写free(p);// 用完归还p = NULL;// 顺手置空,避免悬空指针

其他说明

返回的内存内容是垃圾值,必须先写后读。C 中不要给 malloc 的返回值加 (int *) 之类的强制转换——它会掩盖忘记包含头文件的错误(C++ 中才需要转换,但 C++ 应直接用容器或 new)。分配数组时更推荐 calloc,它顺带做了乘法溢出检查。

calloc

按「元素个数 × 每个大小」申请内存并全部清零,还顺带替你挡住乘法溢出。

函数原型

void *calloc(size_t nmemb, size_t size);

参数

参数类型说明
nmembsize_t元素个数。当它来自外部输入时,交给 calloc 比自己写 malloc(n * size) 更安全——标准要求实现检查 nmemb * size 的乘法溢出
sizesize_t每个元素的大小(字节),惯用 sizeof *arr

返回值

成功返回指向 nmemb * size 字节且全部清零的内存;失败,或 nmemb * size 的乘法会溢出时,返回 NULL。与 malloc 一样,判空是唯一可靠的失败检测手段;POSIX 平台上失败时通常置 errno = ENOMEM,可据此打印错误详情。

示例

int *arr = calloc(n, sizeof *arr);   // 全零,且 n*sizeof 溢出时安全返回 NULL
if (!arr) {
    // 分配失败或元素总字节数溢出
    return -1;
}
// 此处 arr[i] 全部为 0,可直接当计数器数组用
free(arr);

其他说明

推荐

calloc 相比 malloc(n * size) 有两个优势:一是内存清零,二是标准要求实现检查 nmemb * size 的乘法溢出。手写 malloc(n * size) 当 n 来自外部输入时,乘法回绕可能导致分配远小于预期的缓冲区——这是一类经典的堆溢出漏洞。注意:清的是“全零字节”,对指针和浮点数在个别古董平台上不等于 NULL/0.0,现代主流平台可放心。

realloc

把已分配的内存块改成新的总大小,可能整块搬家,原有数据会跟着迁过去。

函数原型

void *realloc(void *ptr, size_t size);

参数

参数类型说明
ptrvoid *旧内存块的指针,必须是 malloc/calloc/realloc 返回的原始地址(不能是块内部的偏移)。可为 NULL,此时等价于 malloc(size)
sizesize_t调整后的新的总大小(字节),不是增量——这是最常见的误用。可以比原来大也可以比原来小;不要用 size == 0 来释放内存(该行为由实现定义,C23 起已改为未定义),释放请用 free

返回值

成功返回新块的指针(原有内容保留到新旧大小中较小者,扩大出来的部分未初始化);失败返回 NULL,此时旧块原封不动、仍然有效,因此必须先把返回值接到临时变量里再判断,否则会把唯一指向旧块的指针冲掉。失败时 POSIX 平台通常置 errno = ENOMEM,可用它打印详情;判空仍是可移植的失败判据。

示例

int *tmp = realloc(p, new_n * sizeof *p);// 先接到临时变量if (tmp == NULL) {    free(p);// 失败:旧块还在,由你决定去留    return -1;}p = tmp;// 成功后才覆盖 p

其他说明

搬家陷阱

realloc 可能原地扩容,也可能“搬家”——把数据复制到新地址并释放旧块。因此:① 必须使用返回值,搬家后旧指针立即失效;② 绝不能写 p = realloc(p, n),失败返回 NULL 会把唯一指向旧块的指针冲掉,造成内存泄漏;③ 其他指向该块内部的指针(别名、迭代位置)在搬家后全部作废,需按偏移量重建。

free

把 malloc 家族借来的内存还给堆;还完指针就作废,重复释放会砸坏堆结构。

函数原型

void free(void *ptr);

参数

参数类型说明
ptrvoid *要归还的内存块指针,必须是 malloc/calloc/realloc 返回的原始地址。传 NULL 是合法的空操作;传栈变量地址、数组中间地址、字符串字面量,或对同一地址释放两次,都是未定义行为

返回值

无返回值。free(NULL) 是标准明确定义的空操作,因此不需要在调用前判空。free 不报告错误,也不会修改传入的指针变量本身——调用后 ptr 立刻变成悬空指针,再读写它属于未定义行为,错误只能靠 AddressSanitizer 一类工具在运行期发现。

示例

free(p);p = NULL;// 立即置空:双重释放变成无害的 free(NULL)free(p);// 安全:free(NULL) 什么也不做

其他说明

禁用行为

三大未定义行为:① 双重释放——同一指针 free 两次,是堆破坏和安全漏洞的高发源;② 悬空指针——free 之后继续读写(use-after-free);③ free 一个并非来自 malloc 家族的指针(栈变量、数组中间地址、字符串字面量)。防御性习惯是 free 后立刻把指针置 NULL,并在调试期启用 AddressSanitizer(-fsanitize=address)或 MSVC 的调试堆来抓现行。

atoi / atol / atof

已过时

把字符串开头的数字读成 int、long、double,失败也只返回 0,无法分辨对错。

函数原型

int atoi(const char *nptr);
long atol(const char *nptr);
double atof(const char *nptr);

参数

参数类型说明
nptrconst char *待转换的字符串。跳过前导空白,解析可选的正负号与数字,遇到第一个不能构成数值的字符即停止,后面的内容被静默丢弃。三个函数参数完全相同,区别只在目标类型:atoi 转 int、atol 转 long、atof 转 double(不是 float)

返回值

成功返回解析出的数值;无法解析时返回 0——而这正是问题所在:合法输入 "0" 与非法输入 "abc" 的返回值完全相同,调用方无从分辨。结果超出目标类型范围时是未定义行为,并且不设置 errno。换句话说,这一族函数没有任何取错误详情的手段;需要错误检测请改用下一条的 strtol 家族。

示例

int a = atoi("0");// 0:合法输入int b = atoi("abc");// 0:非法输入,返回值无法区分!int c = atoi("99999999999");// 溢出:未定义行为double d = atof("3.14xyz");// 3.14:尾部残留被静默忽略

其他说明

缺陷

这一族函数没有任何错误报告机制:解析失败返回 0,与合法输入 "0" 不可区分;结果超出类型范围直接是未定义行为(不设置 errno)。它们只适合“输入已确认合法”的场景,任何面向外部数据的解析都应改用下一条的 strtol 家族。

strtol / strtoul / strtod

推荐

把字符串解析成整数或浮点数,并通过 endptr 和 errno 告诉你在哪停下、是否溢出。

函数原型

long strtol(const char *nptr, char **endptr, int base);
unsigned long strtoul(const char *nptr, char **endptr, int base);
double strtod(const char *nptr, char **endptr);

参数

参数类型说明
nptrconst char *待解析字符串(自动跳过前导空白,再解析可选正负号与数字)
endptrchar **输出参数:函数把“第一个未被消费的字符”的地址写进 *endptr。传 NULL 表示不关心;想做错误检查就必须传,靠比较 *endptr == nptr 判断“一个字符都没解析到”,靠 **endptr != '\0' 判断“数字后还有尾巴”
baseint进制,取值 2~36;0 表示自动识别——0x/0X 前缀按十六进制,0 前缀按八进制,其余按十进制。strtod 没有这个参数(固定按十进制浮点解析,也识别 0x 十六进制浮点、inf、nan)

返回值

成功返回解析出的数值。溢出时返回 LONG_MAX/LONG_MIN(strtoul 返回 ULONG_MAX,strtod 返回 ±HUGE_VAL)并置 errno = ERANGE;完全无法解析时返回 0 且 *endptr == nptr。取错误详情的方式:调用前先 errno = 0,调用后依次检查 endptr 是否前进、errno == ERANGE、尾部是否有残留字符——这三步缺一不可。

示例

char *end;
errno = 0;                             // 调用前必须清零 errno
long v = strtol(s, &end, 10);
if (end == s) {
    // 一个数字都没解析到
} else if (errno == ERANGE) {
    // 溢出,v 已被钳在 LONG_MAX / LONG_MIN
} else if (*end != '\0') {
    // 数字后还有尾巴,如 "12abc"
} else {
    // v 是干净的完整解析结果
}

其他说明

三步检查(endptr 未前进、errno == ERANGE、尾部残留)缺一不可。另有 strtoll/strtoull(C99)对应 long long,strtof/strtold 对应 float/long double。C++ 可用 std::stoi 系(抛异常)或 C++17 的 std::from_chars(无异常、不看 locale、性能最好)。

rand / srand

生成一串伪随机数,srand 决定用哪颗种子起头,同一种子必然得到同一序列。

函数原型

int rand(void);
void srand(unsigned int seed);

参数

rand 无参数;srand 的参数如下。

参数类型说明
seedunsigned int伪随机序列的种子。同一种子必然产生同一序列,这既是复现调试用例的手段,也意味着种子可预测时随机数就可预测。常用 (unsigned)time(NULL),但整个程序只应播种一次——在循环里反复 srand 会让同一秒内取到的值全部相同。不调用 srand 时,行为等同于 srand(1)

其他说明

现代提示

rand 的质量普遍很差:序列周期短、低位随机性弱、rand() % n 存在取模偏差,且绝不可用于任何密码学场景。C++ 请使用 <random>:std::mt19937 配 std::uniform_int_distribution 才是均匀分布的正确写法。纯 C 下,Windows 可用 rand_s/BCryptGenRandom,POSIX 可用 getrandom/arc4random 获取加密级随机数。

abs / labs / llabs

取整数的绝对值,三个版本分别对应 int、long、long long 三种宽度。

函数原型

int abs(int j);

int d = abs(a - b);// 常见用法:两数距离// 陷阱:abs(INT_MIN) 未定义 —— 补码下 |INT_MIN| 超出 int 表示范围if (x != INT_MIN) {    int m = abs(x);// 先排除最小值再取绝对值}

div

一次调用同时算出商和余数,两个结果打包在 div_t 结构体里一起返回。

函数原型

div_t div(int numer, int denom);

参数

参数类型说明
numerint被除数
denomint除数。不能为 0,除零是未定义行为(通常直接触发硬件异常);另外 div(INT_MIN, -1) 的商无法表示,同样是未定义行为

返回值

返回 div_t 结构体本身(不是指针),成员 quot 是商、rem 是余数,二者满足 quot * denom + rem == numer;标准规定商向零截断,因此负数相除时余数与被除数同号。另有 ldiv/lldiv(返回 ldiv_t/lldiv_t)对应 long/long long。函数不报告错误、不设 errno,非法输入直接是未定义行为,须在调用前自行校验除数。

其他说明

历史上它能一条指令同时算出商和余数;现代编译器对相邻的 / 和 % 会自动合并,div 的性能意义已基本消失,但一次调用同时拿到两个结果的语义仍然清晰。

qsort

对任意类型的数组做原地排序,元素之间怎么比大小由你传进去的比较函数决定。

函数原型

void qsort(
    void *base,
    size_t nmemb,
    size_t size,
    int (*compar)(const void *, const void *)
);

参数

参数类型说明
basevoid *待排序数组的首地址
nmembsize_t元素个数(不是字节数)
sizesize_t单个元素的字节数,通常写 sizeof arr[0]
comparint (*)(const void *, const void *)比较函数指针:a<b 返回负数,a==b 返回 0,a>b 返回正数。两个参数指向的是数组元素本身,函数内要先转回真实类型再解引用;返回值必须构成严格弱序(自洽、可传递),否则行为未定义。易错点:整型比较不要写 a - b,会溢出

返回值

无返回值,原地排序。qsort 不报告错误、也没有错误码可查:排序结果不保证稳定(相等元素的相对顺序可能改变),而比较函数不自洽时属于未定义行为,某些实现会越界崩溃——这类问题只能靠自己保证比较函数正确。

示例

int cmp_int(const void *pa, const void *pb) {    int a = *(const int *)pa;// 第一步:void* 转回真实类型再解引用    int b = *(const int *)pb;    return (a > b) - (a < b);// 不要写 a - b:可能溢出(如 INT_MAX - (-1))}qsort(arr, n, sizeof arr[0], cmp_int);

其他说明

比较函数三要素——① 参数固定是两个 const void *,指向的是数组元素本身(排指针数组时它是“指向指针的指针”,要解引用两层);② 内部先转型回元素类型;③ 返回负/零/正,且必须构成严格弱序(自洽、可传递),否则行为未定义,某些实现会越界崩溃。排字符串数组的经典写法:return strcmp(*(const char *const *)pa, *(const char *const *)pb);。C++ 首选 std::sort——比较器可内联,通常明显快于 qsort 的函数指针调用。

bsearch

在已排好序的数组里二分查找,命中返回元素地址,落空返回 NULL。

函数原型

void *bsearch(
    const void *key,
    const void *base,
    size_t nmemb,
    size_t size,
    int (*compar)(const void *, const void *)
);

参数

参数类型说明
keyconst void *指向要查找的键。键的类型不必与数组元素相同,但比较函数必须按“第一个参数是 key”的约定来写
baseconst void *已排序数组的首地址。数组必须事先按同一个比较函数升序排好,否则结果无意义且不会报错
nmembsize_t元素个数
sizesize_t单个元素的字节数,通常写 sizeof arr[0]
comparint (*)(const void *, const void *)比较函数,语义与排序时必须完全一致:第一个参数固定是 key,第二个是数组元素;key<元素返回负数,相等返回 0,key>元素返回正数

返回值

找到时返回指向匹配元素的指针(有多个相等元素时返回其中任意一个,不保证是第一个);找不到返回 NULL,所以使用前必须判空。bsearch 不设置 errno,也无法区分“确实不存在”和“数组没排好序导致漏查”——数组无序时结果是未定义的,不会报错,只会静默找错。

其他说明

两个前提缺一不可——数组必须已按同一个比较函数升序排好,且 compar 的第一个参数固定是 key、第二个是数组元素(键与元素类型不同时要按此约定写)。数组无序时结果是未定义的,不会报错,只会静默找错。

exit / atexit

exit 让程序正常收场并冲刷缓冲,atexit 用来登记退出前要执行的清理函数。

函数原型

void exit(int status);
int atexit(void (*func)(void));

参数

参数类型说明
statusint交还给宿主环境的退出状态。可移植的取值只有 EXIT_SUCCESS(等于 0)和 EXIT_FAILURE,其他值的含义由实现定义。调用后函数不返回,程序就此正常终止
funcvoid (*)(void)要注册的退出回调,必须无参数、无返回值。可注册多个(标准保证至少支持 32 个),程序退出时按注册的逆序依次调用;回调里不要再调用 exit,否则行为未定义

返回值

exit 永不返回,没有返回值可判;程序的成败通过 status 传给宿主环境(EXIT_SUCCESS 表示成功,EXIT_FAILURE 表示失败)。atexit 注册成功返回 0,失败返回非零——失败的典型原因是注册数量超过实现上限(至少 32 个),标准未规定它设置 errno,因此只能靠返回值判断,建议对关键清理逻辑检查其返回值。

示例

void cleanup(void) { puts("bye"); }

int main(void) {
    if (atexit(cleanup) != 0) {
        // 注册失败:回调不会被调用
        return EXIT_FAILURE;
    }
    exit(EXIT_SUCCESS);     // 按逆序调回调,再冲刷并关闭所有 stdio 流
}

其他说明

exit 会按注册的逆序执行所有 atexit 回调、冲刷并关闭打开的流、删除 tmpfile 临时文件;main 中 return n 等价于 exit(n)。另有 _Exit(C99)立即终止、不做任何清理。注意 exit 不会展开调用栈——C++ 中经 exit 退出时局部对象的析构函数不会执行,C++ 程序更应让 main 自然返回。

abort

立刻掀桌子终止进程,不做任何清理,只留下崩溃现场供事后调试。

函数原型

void abort(void);

参数：无。

返回值

不返回。abort 触发 SIGABRT 信号使程序异常终止,不执行 atexit 回调、不冲刷流,因此没有成功/失败之分,也没有错误码可取;错误详情要到进程外面找——Unix 上看 core dump,Windows 上看崩溃报告。

示例

if (invariant_broken) {
    fprintf(stderr, "内部状态损坏,立即终止\n");
    abort();    // 不调用 atexit 回调,不冲刷流,通常生成 core dump
}

其他说明

abort 与 exit 的分工——exit 是“正常收工”,abort 是“出大事了,原地保留现场”。它跳过 atexit 与流冲刷,在 Unix 上产生 core dump、在 Windows 上触发崩溃报告,便于事后调试。assert 失败时内部调用的就是它。MSVC 调试版下 abort 会先弹出中止/重试/忽略对话框。

system

把一整条命令丢给系统 shell 去执行,拼入外部输入就等于开门迎接命令注入。

函数原型

int system(const char *command);

参数

参数类型说明
commandconst char *要交给命令解释器(POSIX 上是 /bin/sh,Windows 上是 cmd.exe)执行的整串命令。传 NULL 时不执行任何命令,仅用于探测系统上是否有可用的命令解释器。严重易错点:整串文本会被 shell 解释,任何拼入其中的外部输入都可能携带 ;、|、&&、反引号等元字符造成命令注入

返回值

char cmd[256];

其他说明

安全警告

system 把整串文本交给 shell 解释,任何拼入命令的外部输入(文件名、表单字段、环境变量)都可能携带 ;、|、&&、反引号等元字符实现命令注入;它还继承当前环境的 PATH,可能被劫持执行同名恶意程序。需要启动子进程时,优先用不经过 shell 的接口:POSIX 的 fork+execv/posix_spawn,Windows 的 CreateProcess。在 setuid 程序中调用 system 应视为绝对禁区。

getenv

分类 3string.h 字符串与内存

C 语言没有内建字符串类型,一切都建立在"以 '\0' 结尾的字符数组"这一约定之上。<string.h> 提供两族函数:str* 系列依赖结尾符工作,mem* 系列按字节数操作任意内存。本章逐一说明常用函数,并特别标注缓冲区溢出、未写结尾符、不可重入等经典陷阱。MSVC 下多数传统函数会触发 C4996 弃用警告,建议改用带边界检查的 _s 安全版本;在 C++ 项目里,能用 std::string / std::string_view 就不要手工摆弄裸字符数组。

strlen 推荐

strcpy / strcpy_s 已过时

把一个字符串连同结尾符整串搬进另一块缓冲区；strcpy_s 多要一个目标容量参数，装不下时报错而不是直接越界写。

禁用

strncpy

最多只往目标里写 n 个字符，原本是为定长记录字段设计的；源串够长时不会补结尾符，并不是"安全版的 strcpy"。

参数

参数类型说明
destchar *目标缓冲区,容量至少为 count 字节;与 src 不得重叠
srcconst char *源字符串,以 '\0' 结尾

返回值

成功:返回 dest。失败:无失败返回值,也不设置 errno;容量不足或参数非法都表现为未定义行为,函数本身不做任何检查,错误只能由调用方在调用前避免。

经典陷阱

strncpy 不是"安全版 strcpy":当 src 长度 ≥ count 时,它不会写结尾 '\0',后续对 buf 调用任何 str* 函数都是未定义行为;而当 src 较短时它又会用 '\0' 把剩余空间全部填满,白白浪费写入。它本是为定长记录字段设计的,做普通字符串复制请改用 strcpy_s 或 snprintf。

strcat / strcat_s 已过时

与 strcpy 同理,strcat 无容量检查且触发 C4996,新代码用 strcat_s。另注意:在循环里反复 strcat 的复杂度是 O(n²),因为每次都要从头找结尾符;大量拼接请记录当前长度或改用 snprintf,C++ 里用 std::string::operator+=。

strcmp / strncmp

strchr / strrchr

strstr

在一段文本里查找某个子串首次出现的位置，也常直接拿返回值真假来判断"这段文字包不包含某个关键词"。

strtok / strtok_s 已过时

按分隔符把一个字符串就地切成一段段记号，逐次取出；strtok_s 把切分进度交给调用方保存，因而可重入、能嵌套和多线程用。

函数原型

参数

参数类型说明
strchar *首次调用传入待切分的串(必须可写,函数会就地把分隔符改写为 '\0',字符串字面量传进去直接崩溃);后续调用传 NULL,表示继续切分上一次的串
delimsconst char *分隔符集合,其中每一个字符都单独算作分隔符(不是把它当成一个整体子串);每次调用都可以传不同的集合

返回值

成功:返回指向下一个记号(token)的指针,该记号已被就地截断为独立字符串。失败/结束:没有更多记号时返回 NULL,不设置 errno。注意连续的分隔符被当作一个处理,不会产生空记号。

状态陷阱

strtok 把切分进度存在一个隐藏的静态变量里,因此不可重入:不能在两个字符串上交替切分,不能在多线程中同时使用,也不能在回调里嵌套调用——后一次会悄悄冲掉前一次的进度。它还会就地改写原串(写入 '\0'),字符串字面量传进去直接崩溃。请改用把状态交给调用方的 strtok_s。另注意:C11 附录 K 的 strtok_s 比 MSVC 版多一个长度参数,两者签名不同,跨平台代码需留意。

memcpy 推荐

按指定字节数把一块内存整体复制到另一处，不认结尾符，结构体和数组都能整块搬，前提是两块区域互不重叠。

函数原型

void *memcpy(void *dest, const void *src, size_t count);

参数

参数类型说明
destvoid *目标内存起点,容量至少 count 字节;与 src 不得重叠,重叠即未定义行为
srcconst void *源内存起点,可读区域至少 count 字节
countsize_t要复制的字节数,通常用 sizeof 计算;它按字节数工作,与元素类型无关

返回值

成功:返回 dest。失败:无失败返回值,也不设置 errno;越界、空指针、区域重叠都是未定义行为,函数不做检查,只能靠调用方在调用前保证参数合法。

示例

double src[4] = {1, 2, 3, 4};
double dst[4];
memcpy(dst, src, sizeof dst);   // 按字节整块复制,数组、结构体皆可

其他说明

区域不可重叠

memcpy 的前提是源和目标互不重叠,重叠即未定义行为——实现可能按任意方向、任意块宽复制,重叠时部分数据会在被读取前就被覆盖。凡是"在同一缓冲区内挪动数据"(如数组元素前移),必须用 memmove。字节数按 sizeof 计算,复制含指针的结构体时复制的是指针值本身(浅拷贝)。

memmove

同样是按字节复制内存，与 memcpy 的区别是允许源和目标重叠，在同一个缓冲区里挪动数据时只能用它。

函数原型

void *memmove(void *dest, const void *src, size_t count);

参数

参数类型说明
destvoid *目标内存起点,容量至少 count 字节;允许与 src 重叠
srcconst void *源内存起点,可读区域至少 count 字节
countsize_t要移动的字节数

返回值

成功:返回 dest。失败:无失败返回值,也不设置 errno;越界或空指针仍是未定义行为,函数只额外保证"重叠也正确",不保证边界安全。

示例

int a[5] = {1, 2, 3, 4, 5};
memmove(a, a + 1, 4 * sizeof(int));  // 整体前移一格:{2,3,4,5,5}

其他说明

与 memcpy 的唯一语义区别:memmove 保证结果等同于"先复制到临时缓冲区再写回",因此重叠也正确。代价是可能略慢;确定不重叠时用 memcpy,拿不准就用 memmove——正确性永远优先。

memset

把一段内存逐字节填成同一个值，最常见的用途是给结构体或缓冲区整块清零，注意填非零值时是按字节生效的。

函数原型

void *memset(void *dest, int ch, size_t count);

参数

参数类型说明
destvoid *要填充的内存起点,可写区域至少 count 字节
chint填充值,先按 unsigned char 截断再逐字节写入。最常用的是 0;填非零值时要记得它是按字节生效的(填 1 得到的 int 是 0x01010101,而不是 1)
countsize_t填充的字节数。写数组时应传 sizeof buf,不要误写成 sizeof(char*)

返回值

成功:返回 dest。失败:无失败返回值,也不设置 errno;参数顺序写反(如 memset(&cfg, sizeof cfg, 0))编译不报错、运行也不报错,只是什么都没清干净,须靠代码评审发现。

其他说明

现代提示

memcmp

逐字节比较两块内存的前若干字节是否一致，不在结尾符处停下，常用于比对文件魔数等定长二进制数据。

参数类型说明

rhsconst void *参与比较的内存块 2,可读区域至少 count 字节

不要用 memcmp 比较整个结构体判等:成员之间的填充字节内容不确定,相等的结构体可能比出不等。逐成员比较才可靠。

memchr

在给定长度的内存范围里找某个字节第一次出现的位置，不依赖结尾符，适合处理中间可能含 '\0' 的二进制数据。

参数类型说明

其他说明

相当于"带长度上限、不依赖结尾符的 strchr",处理网络包、文件块等可能内含 '\0' 的数据时应选它。

strerror / strerror_s

把 errno 之类的错误码翻译成人能看懂的文字描述；strerror 返回共享静态缓冲区，strerror_s 写进调用方自备的缓冲区，多线程下更稳。

函数原型

char *strerror(int errnum);

参数

参数类型说明

bufchar *仅 _s 版:接收错误描述文字的调用方缓冲区
bufszrsize_t仅 _s 版:buf 的容量(字节),含结尾符;描述过长时会被截断,128 字节一般够用

返回值

成功:strerror 返回指向错误描述字符串的指针;strerror_s 返回 0,描述被写入调用方的 buf(过长时截断)。失败:strerror 对未知错误码仍返回一段(实现定义的)文字,不会返回 NULL;strerror_s 参数非法时返回非零错误码。错误详情:这一对函数本身就是"取错误详情"的手段——先保存 errno,再交给它们转成可读文字。

strerror 返回的指针可能指向内部静态缓冲区,下一次调用会覆盖其内容,多线程下不安全(MSVC 触发 C4996);strerror_s 写入调用方缓冲区,无此问题。C++ 中可用 std::system_error / std::generic_category().message(errnum) 获得等价信息。

分类 4wchar.h 宽字符(Windows 开发重点)

Windows 内核与 Win32 API 原生使用 UTF-16,wchar_t 在 MSVC 下固定为 16 位;而 Linux/macOS 上 wchar_t 是 32 位(通常存 UTF-32)。因此宽字符 API 在 Windows 开发中地位远高于其他平台:凡涉及中文路径、注册表、窗口标题,几乎都绕不开 wchar_t 与 L"..." 字面量。本章函数与 string.h/stdio.h 的窄字符版本一一对应,记住"str→wcs、printf→wprintf"的映射规律即可。MSVC 下不安全版本(如 wcscpy)同样触发 C4996 警告,应优先使用 _s 后缀版本。

速览

本章速览——宽字符版本的字符串与 I/O 工具集,重点在「以宽字符为单位计数」和「窄宽流不可混用」这两个坑。

wcslen

推荐

数出宽字符串里有多少个 wchar_t 单元,分配内存时还要乘 sizeof(wchar_t) 才是字节数

函数原型

size_t wcslen(const wchar_t *str);

参数

参数类型说明
strconst wchar_t *以 L'\0' 结尾的宽字符串;不可为 NULL,也不可指向没有终止符的数组,否则函数会一直越界读取(未定义行为)

返回值

返回字符串中 wchar_t 单元的个数,不包含终止符。该函数没有失败返回值,也不设置 errno——传入非法指针不是"失败"而是未定义行为,只能由调用方保证前置条件。注意返回的是"宽字符数"而非字节数;需要字节数(例如 malloc 时)必须写成 wcslen(s) * sizeof(wchar_t),再为终止符多留一个元素。

示例

const wchar_t *s = L"你好, Windows";size_t n = wcslen(s);// 11 —— 每个汉字算 1 个 wchar_tsize_t bytes = n * sizeof(wchar_t);// Windows 下为 22 字节wchar_t *copy = malloc((n + 1) * sizeof(wchar_t));// 别忘了给 L'\0' 留位置

其他说明

UTF-16 中超出基本平面的字符(如部分 emoji)占两个 wchar_t(代理对),wcslen 会计为 2——它数的是编码单元而非"用户可见字符"。需要统计真正的字符数或显示宽度时,必须自行处理代理对,或改用 Win32 的文本 API。

wcscpy_s

推荐

把一个宽字符串整体复制到目标缓冲,复制前先核对容量,放不下就返回错误而不是越界写

函数原型

参数

参数类型说明
destwchar_t *目标缓冲区,接收复制结果;不可为 NULL,也不可与 src 内存重叠
destszrsize_t目标缓冲区的元素容量(宽字符个数,不是字节数),含终止符所占的那个位置;推荐一律写 _countof(buf),误写成 sizeof(buf) 会让容量虚高一倍从而溢出

最常见的错误是把 sizeof(buf)(字节数)当成 destsz 传入——宽字符版本必须传元素个数,统一用 _countof(buf) 可同时兼容窄/宽两种缓冲区。C++ 中直接用 std::wstring 赋值即可,无容量问题。

wcscat_s

推荐

参数类型说明

wcscmp / wcsncmp

按编码值逐个比较两个宽字符串的大小,wcsncmp 只比前 n 个宽字符,常用来判断前缀

函数原型

int wcscmp(const wchar_t *lhs, const wchar_t *rhs);
int wcsncmp(const wchar_t *lhs, const wchar_t *rhs, size_t n);

参数

参数类型说明
lhsconst wchar_t *参与比较的第一个宽字符串,以 L'\0' 结尾
rhsconst wchar_t *参与比较的第二个宽字符串,以 L'\0' 结尾
nsize_t仅 wcsncmp:最多比较的宽字符个数;遇到 L'\0' 会提前停止,常用于前缀判断(如判断 L"https://" 传 8)

返回值

逐个比较 wchar_t 的数值:两串相等返回 0,lhs 排在前(首个不同码元更小)返回负值,排在后返回正值。具体数值大小无意义,只应判断符号。这两个函数没有"失败"状态;比较的是码元值而非本地化排序,所以结果与用户语言习惯无关。

const wchar_t *ext = L".txt";

if (wcscmp(ext, L".txt") == 0)         { /* 精确匹配扩展名 */ }

其他说明

现代提示

Windows 文件系统不区分大小写,比较路径应使用 _wcsicmp(MSVC 扩展)或 Win32 的 CompareStringOrdinal;需要按用户语言排序时用 wcscoll 或 Win32 CompareStringEx,不要用 wcscmp 做界面排序。

在宽字符串里查找某个宽字符或某段子串,找到返回指向该处的指针,找不到返回 NULL

函数原型

wchar_t *wcschr(const wchar_t *str, wchar_t ch);
wchar_t *wcsstr(const wchar_t *str, const wchar_t *substr);

参数

参数类型说明
strconst wchar_t *被搜索的宽字符串,以 L'\0' 结尾
chwchar_t仅 wcschr:要查找的单个宽字符,写成 L'.' 这样的宽字符字面量;传 L'\0' 则返回指向终止符的指针

const wchar_t *file = L"C:\\data\\report.csv";

swprintf_s

推荐

把数字、字符串等按格式拼装成一个宽字符串写进缓冲区,即宽字符版的字符串格式化

函数原型

int swprintf_s(wchar_t *buffer, size_t sizeOfBuffer, const wchar_t *format, ...);

参数

参数类型说明
bufferwchar_t *接收格式化结果的输出缓冲区;失败时会被置为空串
sizeOfBuffersize_t缓冲区容量,按宽字符数计(不是字节数),含终止符位置;用 _countof(buf)
formatconst wchar_t *宽字符格式串,如 L"第 %d 行: %ls"。MSVC 陷阱:宽格式串里 %s 默认按 wchar_t* 解释(与 C 标准相反),跨平台代码应显式写 %ls(宽串)/ %hs(窄串)

示例

wchar_t msg[64];

                   L"第 %d 行: %ls", 42, L"解析失败");  // 显式 %ls 更可移植

    // 缓冲区不够,swprintf_s 不会截断,msg 已成空串
}

其他说明

与 snprintf 的关键差异:① snprintf 空间不足时安全截断,并返回"假如空间够会写多少"的长度,可据此二次分配;而 swprintf_s 空间不足视为运行期约束违规——触发无效参数处理程序、缓冲区置空串、返回负值,不截断也不告诉你需要多大。② 长度单位是宽字符数而非字节。③ MSVC 特有陷阱:宽字符格式化函数里 %s 默认按 wchar_t* 解释(与 C 标准相反),跨平台代码应显式写 %ls(宽)/%hs(窄)。需要"截断也算成功"的语义时,用 _snwprintf_s(buf, size, _TRUNCATE, ...)。

swscanf_s

从一个宽字符串里按格式抠出数字和文本,是宽字符版的反向格式化,专用于解析

函数原型

int swscanf_s(const wchar_t *buffer, const wchar_t *format, ...);

参数

参数类型说明
bufferconst wchar_t *待解析的宽字符串,以 L'\0' 结尾;函数不会修改它
formatconst wchar_t *格式串,如 L"%d %ls";转换说明与 wscanf 一致
...可变参数接收解析结果的变量地址。_s 版本的硬性规定:每个 %s / %c / %[] 之后必须额外紧跟一个缓冲区容量实参(宽字符数,类型为 unsigned/rsize_t),漏传不会报编译错误,却会在运行期崩溃或读到垃圾

返回值

返回成功匹配并赋值的字段个数;若在第一个字段匹配成功前就发生匹配失败或输入耗尽,返回 EOF。判断解析是否完整,应把返回值与期望的字段数相比较,而不是只判断非零。

示例

wchar_t name[32];
int id;
// _s 版本:每个 %s / %c 之后必须额外传缓冲区容量(宽字符数)
int got = swscanf_s(L"1024 张三", L"%d %ls",
                    &id, name, (unsigned)_countof(name));
if (got != 2) {
    // 解析失败:字段数不足
}

其他说明

漏传 %s/%c 后面的容量参数是 _s 系 scanf 最常见的事故点——编译期完全无提示,运行期直接崩溃或读到垃圾。复杂解析建议改用 wcstol / wcstod 等函数逐段转换,错误可控性更好,也不必与可变参数的类型约定搏斗。

wcstok_s

推荐

按指定的分隔符集合把宽字符串就地切成一段段记号,切分进度由调用方变量保存

函数原型

wchar_t *wcstok_s(wchar_t *str, const wchar_t *delim, wchar_t **context);

参数

参数类型说明
strwchar_t *首次调用传待切分的字符串,后续调用一律传 NULL 以继续上次的位置。该串会被就地改写(分隔符处写入 L'\0'),因此不能传字符串字面量或 const 串,必要时先复制一份
delimconst wchar_t *分隔符集合:其中每一个宽字符都单独作为分隔符,而不是把整串当作一个分隔序列;每次调用可以传不同的集合

返回值

返回指向下一个记号(token)首字符的指针,该记号已被就地补上 L'\0';没有更多记号时返回 NULL,这是循环的终止条件。参数非法时同样返回 NULL 并触发无效参数处理程序;函数不设置 errno。

wchar_t path[] = L"C:\\Users\\admin\\Desktop";  // 数组而非字面量指针,可被改写

     p != NULL;

    // 依次得到 "C:" "Users" "admin" "Desktop"
}

其他说明

显式的 context 使其线程安全,也允许嵌套切分两个字符串——这正是旧 wcstok/strtok 靠静态变量做不到的,后者已属 已过时 用法。注意 MSVC 的 wcstok 本身在不同版本间签名有过变化,统一用 wcstok_s 最稳妥。

wcstol / wcstod

把宽字符串开头的数字文本转成 long 或 double,并带出解析停在哪个字符上

函数原型

double wcstod(const wchar_t *str, wchar_t **endptr);

参数

参数类型说明
strconst wchar_t *待转换的宽字符串,允许带前导空白与正负号;转换从第一个非空白字符开始,遇到不合法字符即停止
endptrwchar_t **输出参数:函数写入指向第一个未被转换的字符的指针。可传 NULL 表示不关心,但那样就无法区分"解析失败"与"值确实是 0"

const wchar_t *text = L"8080/api";

}

fgetws / fputws

从文件流按行读入一行宽字符,或把一段宽字符串写出到流,是宽字符版的行读写

函数原型

wchar_t *fgetws(wchar_t *str, int count, FILE *stream);
int fputws(const wchar_t *str, FILE *stream);

参数

参数类型说明
strwchar_t * / const wchar_t *fgetws:接收读入内容的缓冲区,行尾换行符 L'\n' 会被保留在其中。fputws:要写出的宽字符串,函数不会自动补换行,需要换行须自己写在串里

返回值

    }
    fclose(fp);
}

其他说明

流的宽/窄取向在首次 I/O 时锁定,同一 FILE* 上混用 fgets 与 fgetws 属未定义行为,必要时可用 fwide 显式设定取向。MSVC 特有的 ccs=UTF-8 / ccs=UTF-16LE 模式让运行库在读写时自动做 UTF 转码,是 Windows 下处理 Unicode 文本文件的实用捷径(非标准 C,跨平台代码需另行封装)。

mbstowcs_s / wcstombs_s

函数原型

isalpha

判断一个字符是不是字母,是词法分析切分单词、校验标识符首字符时的第一道过滤。

函数原型

int isalpha(int c);

参数

参数类型说明
cint待判定的字符。合法取值只有两类:能表示为 unsigned char 的值(0~UCHAR_MAX)或宏 EOF;传入可能为负的 char 是未定义行为,一律写成 (unsigned char)c。判定"是否为字母"的具体范围受当前 locale 影响,默认 "C" locale 下即 a-z、A-Z。

返回值

成功判定为字母时返回非零值(具体数值不保证是 1,不要写 == 1);不是字母则返回 0。本函数没有"失败"状态,也不设置 errno——传入非法值不会返回错误码,而是直接进入未定义行为,因此无从事后取错误详情,只能靠调用前正确强转来预防。

示例

const char *s = "Hello, 2026!";
int n = 0;
for (int i = 0; s[i]; i++)
    if (isalpha((unsigned char)s[i]))  // 强转是必须的,见本章"负值 char 陷阱"
        n++;
// n == 5("Hello")

其他说明

在非 "C" locale 下,某些扩展字符(如 Latin-1 的带音标字母)也可能被判定为字母;需要严格 ASCII 语义时不要依赖 locale,自己写 (c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z') 反而更可靠。C++ 中对应 <cctype> 的 std::isalpha,同样的坑原样存在。

isdigit

判断一个字符是不是 0~9 的十进制数字,扫描数字串、校验输入格式时用它逐字符探路。

函数原型

int isdigit(int c);

参数

参数类型说明
cint待判定的字符,判定它是否为十进制数字 '0'~'9'。合法取值同样只有"可表示为 unsigned char 的值"或 EOF,传 char 前先强转 (unsigned char)。

返回值

成功:c 为 '0'~'9' 之一时返回非零;否则返回 0。没有失败态与 errno,非法输入属未定义行为而非可查询的错误。isdigit 与 isxdigit 是标准中唯二不受 locale 影响的分类函数,任何环境下都只认这十个字符。

示例

// 手工解析非负整数(atoi 的骨架)
int v = 0;
while (isdigit((unsigned char)*p)) {
    v = v * 10 + (*p - '0');  // '0'~'9' 保证连续,可直接减
    p++;
}

其他说明

注意它不识别全角数字、上标数字等 Unicode 数字——那些需要宽字符或第三方库处理。它只做"是不是"的判定,真正把数字串转成数值应交给 strtol 一类函数。

isalnum

判断一个字符是不是字母或数字(下划线不算),常用于校验标识符、用户名和过滤非法输入。

函数原型

int isalnum(int c);

参数

参数类型说明
cint待判定的字符,判定它是否为字母或数字,语义上等价于 isalpha(c) || isdigit(c)。合法取值为可表示为 unsigned char 的值或 EOF;注意下划线 _ 不算,它属于标点(见 ispunct)。

返回值

成功:c 是字母或十进制数字时返回非零;否则返回 0。无失败态、不设置 errno,非法参数为未定义行为,无错误详情可取。字母部分随 locale 变化,数字部分恒为 '0'~'9'。

示例

// 校验标识符:首字符为字母或下划线,其余为字母数字或下划线
int is_ident(const char *s) {
    if (!isalpha((unsigned char)*s) && *s != '_') return 0;
    for (s++; *s; s++)
        if (!isalnum((unsigned char)*s) && *s != '_') return 0;
    return 1;
}

isupper / islower

分别判断一个字母是大写还是小写;非字母时两者都返回 0,所以不能拿一个取反当另一个用。

函数原型

int isupper(int c);

参数

参数类型说明
cintisupper 判定 c 是否为大写字母(默认 locale 下即 A-Z),islower 判定是否为小写字母(即 a-z)。合法取值为可表示为 unsigned char 的值或 EOF,传 char 前必须强转 (unsigned char)。

返回值

成功:命中各自类别时返回非零;否则返回 0。无失败态、不设置 errno,非法输入为未定义行为、无错误详情可取。易错点:对数字、标点等非字母字符两者都返回 0——即"不是大写"并不等于"是小写"。

示例

// 统计大小写分布

for (const char *p = s; *p; p++) {
    if (isupper((unsigned char)*p)) up++;
    else if (islower((unsigned char)*p)) lo++;
}

其他说明

不要用 c >= 'A' && c <= 'Z' 之外还依赖 'a' - 'A' == 32 这类 ASCII 假设做判定——EBCDIC 平台上字母甚至不连续;分类交给库函数最稳。

函数原型

参数

返回值

成功:若 c 有对应的大写/小写形式则返回转换结果,否则原样返回 c——因此对数字、标点直接调用是安全的,无需先用 isupper/islower 判断。没有失败态、不设置 errno;传入非法值属未定义行为,无错误码可查。返回类型是 int,写回 char 数组前应显式强转以消除收窄警告。

判断字符是不是标点符号,标准按排除法定义,下划线、$、@ 也都算,过滤文本时别误伤。

返回值

负值 char 陷阱 未定义行为

这是整个 <ctype.h> 最重要、也最常被忽略的坑,值得单独一条讲透。

char c = /* 从文件或网络读来的字节,比如 0xC3(UTF-8 多字节序列的一部分)*/;isalpha(c);// 错!若 char 有符号,0xC3 变成 -61,未定义行为isalpha((unsigned char)c);// 对:先转 unsigned char,得到 195,合法

坑的成因:所有 is*/to* 函数的合法输入只有两类——能表示为 unsigned char 的值(0~UCHAR_MAX),或宏 EOF(通常为 -1)。而 char 在多数平台(x86 的 MSVC、gcc、clang 默认)是有符号的,任何 ≥0x80 的字节存进 char 都变成负数。把这个负数直接传给 isalpha,既不在 0~255 内也不是 EOF,行为未定义。

坑的现实表现:glibc 等实现用查表实现这些函数,负下标会读到表格前面的内存——多数时候"碰巧能跑",返回随机结果;MSVC 的 Debug 运行库则会直接弹出断言失败对话框。纯 ASCII 测试数据永远触发不了,一旦用户输入中文、法文或任何非 ASCII 字节就爆——典型的"测试全绿、上线就崩"。

正确姿势:

// 1. 逐字符处理字符串:强转 unsigned charif (isalpha((unsigned char)s[i])) { ... } // 2. 处理 getchar()/fgetc() 的返回值:保持 int,不要提前存进 charint ch;// int 才能同时容纳 0~255 和 EOFwhile ((ch = getchar()) != EOF)    if (isdigit(ch)) { ... }// ch 本来就合法,无需强转

注意第 2 种情形恰好说明了为什么参数类型是 int:是为了容纳 EOF,而不是欢迎任意负数。EOF 传入是合法的且所有 is* 函数对它返回 0。

现代提示

把 isalpha((unsigned char)c) 当成肌肉记忆;团队里可封装一层 static inline int my_isalpha(char c) { return isalpha((unsigned char)c); } 一劳永逸。C++ 同理:std::isalpha 的 <cctype> 版本继承同样的约束,给 std::find_if 传裸 ::isalpha 处理 std::string 是经典错误;另外注意还存在 <locale> 中的模板重载 std::isalpha(ch, loc),两者签名不同,混用会导致费解的编译错误。

atan2

推荐 双参数反正切:由坐标 (x, y) 直接求方向角,实战中几乎总应替代 atan。

由纵、横两个坐标分量求点相对原点的方位角,靠 x、y 各自的符号还原出完整象限,x 为 0 也不会除零。

函数原型

参数

参数类型说明

返回值

成功返回点 (x, y) 相对原点的极角,范围 (-π, π],单位弧度;x、y 同时为 0 时结果由实现定义(通常为 0),除此之外没有失败路径,不设 errno。

fmod

浮点取余。% 运算符只接受整数,对 double 求余必须用它。

求两个浮点数相除后剩下的余数,填补 % 只能用于整数的空白,常用来把角度、相位归一化到一个周期内;余数符号跟着被除数走。

返回值

成功返回 x - trunc(x/y)*y,绝对值小于 |y|,符号与 x 相同——这一点与整数 % 的截断语义一致;失败(y 为 0)返回 NaN 并置 errno = EDOM,可用 isnan() 或 errno 判定。

hypot

现代提示 直角边求斜边(C99),专为规避中间量溢出而生。

由两条直角边算斜边长度,也就是两点间的直线距离;内部先缩放再开方,边长极大或极小时不会像 sqrt(x*x+y*y) 那样中途溢出。

函数原型

double hypot(double x, double y);

参数

参数类型说明
xdouble第一条直角边(或两点的横坐标差);允许极大或极小,内部先缩放再开方,不会中途上溢/下溢
ydouble第二条直角边(或两点的纵坐标差),规则同 x

返回值

成功返回 √(x²+y²);即使 x、y 大到其平方会溢出,只要结果本身可表示就正确。只有结果本身超出 double 范围才失败,返回 INFINITY 并置 errno = ERANGE。

示例

double x = 3e200, y = 4e200;printf("%g\n", sqrt(x*x + y*y));// inf:x*x 已溢出成无穷printf("%g\n", hypot(x, y));// 5e+200:内部先缩放再开方double dist = hypot(x2 - x1, y2 - y1);// 两点距离的安全写法

其他说明

cbrt

立方根(C99),对负数也正确。

求实数的立方根,负数照样能算并给出同号结果,这正是它优于 pow(x, 1.0/3) 的地方,精度也更好。

double cbrt(double x);

参数

参数类型说明

返回值

其他说明

这正是它相对 pow(x, 1.0/3) 的价值:后者对负数直接 NaN,且精度更差。

三个分类宏,分别查一个浮点值是不是 NaN、是不是 ±无穷、是不是有限数;由于 NaN 与自身都不相等,只能靠它们检出脏数据。

三者实际是类型泛化宏而非函数,原型中的 double 只表意:传 float、double、long double 都能正确工作,因此不可对其取地址。

返回值

条件成立返回非零(真),否则返回 0。三者互斥且完备:任何浮点值恰属于 NaN、无穷、有限数三类之一(有限数含普通数、非规格化数与 ±0)。宏不设置 errno,没有失败路径。

示例

double bad = sqrt(-1.0);// NaNdouble big = 1.0 / 0.0;// +INFINITY(浮点除零不崩溃)printf("%d\n", bad == bad);// 0!NaN 不等于任何值,包括自己if (isnan(bad))   puts("是 NaN");if (isinf(big))   puts("是无穷");if (!isfinite(x)) return -1;// 入口处拦截脏数据的惯用检查

其他说明

禁用

不要写 x == NAN 来判断——由于 NaN 不等于任何值,该表达式恒为假。老代码里的 x != x 技巧虽然等价于 isnan,但在 -ffast-math 下会被优化掉,一律改用宏。

f 后缀 float 版

现代提示 C99 起,本章每个函数都有 f 后缀的 float 版与 l 后缀的 long double 版。

本章每个函数的单精度分身(sqrtf、powf、fabsf)与扩展精度分身(sqrtl 等),让 float 数据全程走单精度通路,省掉来回转 double 的开销。

函数原型

float sqrtf(float x);
float powf(float x, float y);
float fabsf(float x);
long double sqrtl(long double x);

参数

参数类型说明
x(f 版)float单精度输入,float 进、float 出,全程走单精度通路,不隐式提升为 double;配套的浮点字面量也要带 f 后缀,否则按 double 计算
y(powf)floatpowf 的指数,同为单精度,含义与 pow 的 y 一致
x(l 版)long double扩展精度输入,如 sqrtl;各平台的实际位宽不同(MSVC 上 long double 等同 double)

返回值

语义与对应的 double 版完全一致,仅精度与类型不同:成功返回同类型的计算结果,失败时同样返回 NaN/±INFINITY 并按各自规则设置 errno(EDOM 或 ERANGE),取错误详情的方式也相同。

示例

float len = sqrtf(dx*dx + dy*dy);// 全程单精度,无隐式转 doublefloat s   = sinf(t * 3.14159265f);// 字面量也要带 f,否则按 double 算float a   = fabsf(-1.5f);// 1.5f

其他说明

对 float 变量调用 sqrt 会先提升为 double、算完再截回,既浪费时间又无精度收益;图形、音频、嵌入式等 float 密集场景应坚持用 f 版。C++ 中直接用 <cmath> 的 std::sqrt,重载会按参数类型自动选择,后缀就此退休。

分类 7time.h 时间日期

<time.h> 提供两套时间表示:一是 time_t 表示的“日历时间”(通常是自 1970-01-01 00:00:00 UTC 起的秒数),二是 struct tm 表示的“拆分时间”(年月日时分秒各一个字段)。两者之间用 mktime/localtime_s/gmtime_s 互相转换,格式化输出交给 strftime。此外还有测 CPU 耗时的 clock 和 C11 引入的高精度 timespec_get。本章的两大经典陷阱——tm_year 要加 1900、tm_mon 从 0 起——请务必先看 struct tm 一节。

现代提示

C++ 项目请优先使用 std::chrono(C++11 起):类型安全的时长与时间点运算,C++20 还内建了日历与时区库,能从编译期杜绝“秒当毫秒用”这类单位错误。<time.h> 主要用于 C 代码和与旧接口交互。

速览

本章速览——时间只有三种形态:秒级的 time_t、拆开的 struct tm、给人看的字符串;本章函数做的全是它们之间的来回搬运。

函数一句话说明备注
time取当前日历时间,秒级时间戳time_t 的内部编码由实现定义,别拿它直接做加减,失败时返回 (time_t)-1。
clock返回程序耗用的处理器时钟数不是墙钟时间;须除以 CLOCKS_PER_SEC 才得到秒,多线程程序里含义会失真。
difftime求两个时间点相差多少秒唯一可移植的时间差算法,结果是 double 推荐。
struct tm分解时间:年月日时分秒的结构tm_year 以 1900 为起点、tm_mon 从 0 计,差一错误的重灾区。
mktime分解时间归一化并转回 time_t按本地时区解释,并就地修正越界字段;tm_isdst 置 -1 才让它自行判断夏令时。
localtime_s / gmtime_s时间戳转本地时区或 UTC 分解时间取代返回静态缓冲、非线程安全的 localtime/gmtime 已过时;注意 C11 附录 K 与 MSVC 版参数顺序相反 推荐。
strftime按格式把分解时间输出为字符串返回 0 只代表缓冲区不足,必须检查;用它替代定长输出的 asctime/ctime 已过时。
timespec_get取带纳秒字段的当前时间C11 起提供,基准传 TIME_UTC;实际精度取决于系统,别默认真有纳秒级分辨率 推荐。

time

读取系统当前的日历时间,通常就是 1970 年至今的秒数,程序里问“现在几点”都从它开始。

函数原型

time_t time(time_t *arg);

参数

参数类型说明
argtime_t *可为 NULL,惯用写法就是传 NULL、只取返回值;非空时当前日历时间会同时写入 *arg,此时返回值与 *arg 内容相同

返回值

成功返回当前日历时间(time_t);失败(极罕见,如系统时钟不可用)返回 (time_t)(-1);标准未规定它设置 errno,因此拿不到更细的错误原因,只能按“时钟不可用”处理。

示例

time_t now = time(NULL);            // 惯用写法:传 NULL,只用返回值
printf("since epoch: %lld s\n", (long long)now);

其他说明

time_t 是什么:标准只说它是“能表示时间的算术类型”,但在所有主流平台上它就是“1970-01-01 00:00:00 UTC 至今的秒数”(Unix 时间戳),现代系统均为 64 位整数。打印或存储时先强转 long long,不要假定它是 int 或 long。

clock

测程序自启动以来烧掉的处理器时间,除以 CLOCKS_PER_SEC 换成秒,用来给一段代码算性能账。

函数原型

clock_t clock(void);

参数：无。

返回值

成功返回程序启动以来消耗的处理器时间,单位是“时钟节拍”,除以宏 CLOCKS_PER_SEC 才折算成秒;失败(处理器时间不可用或无法表示)返回 (clock_t)(-1);标准不提供额外的错误详情接口,只能靠与 (clock_t)(-1) 比较来判断。

示例

clock_t t0 = clock();
heavy_work();                        // 被测代码
clock_t t1 = clock();
printf("CPU: %.3f s\n", (double)(t1 - t0) / CLOCKS_PER_SEC);

其他说明

注意它测的是 CPU 时间:程序在 sleep、等 I/O 时它几乎不走;多线程满载时它可能比墙钟快好几倍(POSIX 下累计所有线程)。要测“实际过了多久”请用 timespec_get 或平台高精度计时器(Windows 的 QueryPerformanceCounter);另外 MSVC 的 clock 实测返回的是墙钟时间,与标准语义不符,跨平台代码别依赖它。

difftime

算出两个时间点相隔多少秒,是标准里唯一保证可移植的时间相减方式,结束时刻要写在前面。

函数原型

double difftime(time_t end, time_t beg);

参数

参数类型说明
endtime_t较晚的时间(结束时刻)。易错点:它排在第一个,与“开始在前”的直觉相反,写反会得到负数
begtime_t较早的时间(起始时刻)

返回值

成功返回 end - beg 的差值,以秒计的 double(可为负,代表参数写反或时钟回拨);该函数没有失败返回值,也不设置 errno——只要两个实参是有效的 time_t,结果就有意义,无需取错误详情。

示例

time_t start = time(NULL);
run_task();
double secs = difftime(time(NULL), start);   // 注意:晚的在前
printf("elapsed: %.0f s\n", secs);

其他说明

存在的意义:标准不保证 time_t 能直接做减法(理论上可以是任意算术类型),difftime 是可移植的减法。实践中直接 t1 - t0 也能工作,但写库代码时用它更稳妥。参数顺序是“结束在前、开始在后”,与直觉相反,容易写反得到负数。

struct tm

把时间摊开成年月日时分秒各一个字段的结构体,是时间戳和人类可读日期之间的中转站。

函数原型

struct tm {
    int tm_sec;
    int tm_min;
    int tm_hour;
    int tm_mday;
    int tm_mon;
    int tm_year;
    int tm_wday;
    int tm_yday;
    int tm_isdst;
};

参数

参数类型说明
tm_secint秒,取值 [0,60];上限 60 是留给闰秒的,别按 [0,59] 做断言
tm_minint分,取值 [0,59]
tm_hourint时,取值 [0,23],24 小时制
tm_mdayint日,取值 [1,31];本结构中唯一从 1 起的字段,显示时别顺手也给它 +1
tm_monint月,取值 [0,11],0 起:0 = 一月;显示要 +1,把用户输入的月份填进来要 -1
tm_yearint距 1900 的年数,加 1900 才是公历年份(2026 年存的是 126);反向填写时要减 1900
tm_wdayint星期,取值 [0,6],0 = 周日;由转换函数填出,mktime 会忽略输入值并重算
tm_ydayint一年中的第几天,取值 [0,365];同样由转换函数填出,mktime 会重算
tm_isdstint夏令时标志:>0 表示实行、0 表示不实行、<0 表示未知。手工构造 tm 时设为 -1,让 mktime 自己判断

返回值

本条目是类型定义而非函数,没有返回值;它作为 mktime 的输入、localtime_s/gmtime_s 的输出使用,字段是否有效由对应函数的返回值决定,出错详情要看那些函数而不是本结构。

示例

// 千年虫式经典 bug:直接打印 tm_year 得到 126printf("%d-%02d-%02d\n",       t.tm_year + 1900,// 正确:126 + 1900 = 2026       t.tm_mon  + 1,// 正确:7 + 1 = 8 月       t.tm_mday);// mday 本来就从 1 起,不加

其他说明

高频翻车点

“年份显示成 126”“日期总是差一个月”几乎全是忘了 +1900 / +1。规律可以这样记:凡是当“数组下标/偏移量”用的从 0 起(月、星期、年内天数),凡是人类日历上直接念出来的从 1 起(日)。

mktime

把填好的年月日按本地时区折算回时间戳,顺手把越界字段进位归一,做日期加减最省事的办法。

函数原型

time_t mktime(struct tm *tp);

参数

参数类型说明
tpstruct tm *要转换的分解时间,按本地时区解释;会被原地修改——越界字段归一化(如“1 月 45 日”变成 2 月 14 日),并回填 tm_wday/tm_yday。调用前把 tm_isdst 置 -1,夏令时交由实现判断

返回值

成功返回 *tp 对应的日历时间 time_t,同时 *tp 已被归一化;失败(时间无法用 time_t 表示,例如年份超出范围)返回 (time_t)(-1),此时 *tp 的内容不可信;标准不规定 errno,只能靠这个哨兵值判断。

示例

struct tm t = {0};t.tm_year = 2026 - 1900;  t.tm_mon = 0;  t.tm_mday = 45;// “1 月 45 日”t.tm_isdst = -1;// 夏令时交给它判断mktime(&t);// 归一化为 2 月 14 日,并填好星期几printf("%d-%02d-%02d wday=%d\n",       t.tm_year + 1900, t.tm_mon + 1, t.tm_mday, t.tm_wday);

其他说明

“归一化”是它最好用的隐藏功能:字段允许越界,越界部分自动进位/借位。于是“某天 +30 天”“这个月最后一天是几号”“某日期是星期几”都不用自己写闰年判断——把字段改了再调一次 mktime 即可。注意它按本地时区解释输入;标准 C 没有对应的 UTC 版本(POSIX 有 timegm,MSVC 有 _mkgmtime)。

localtime_s / gmtime_s 推荐

把时间戳拆成年月日时分秒,前者按本地时区、后者按 UTC;结果写进调用者自备的缓冲,因而线程安全。

函数原型

errno_t localtime_s(struct tm *result, const time_t *timer);
errno_t gmtime_s(struct tm *result, const time_t *timer);

参数

参数类型说明
resultstruct tm *调用者提供的输出缓冲,转换结果写入这里;localtime_s 填本地时间,gmtime_s 填 UTC 时间
timerconst time_t *要转换的日历时间(指针,不是值);通常传 &now
参数顺序易错点:上面是 MSVC 版本(目标在前:localtime_s(&result, &timer));C11 附录 K 版本的顺序正好相反:localtime_s(&timer, &result)。POSIX 的 localtime_r(&timer, &result) 又与 MSVC 的 _s 相反。跨平台代码务必按目标平台核对

返回值

MSVC 版:成功返回 0,失败返回错误码(errno_t,如实参为空指针时的 EINVAL),错误详情就在这个返回值里;C11 附录 K 版:成功返回 result 指针,失败返回 NULL。两者都在失败时不保证 *result 的内容,必须先判返回值再读字段。

示例

time_t now = time(NULL);
struct tm local;
if (localtime_s(&local, &now) == 0)          // MSVC 参数顺序
    printf("%d:%02d\n", local.tm_hour, local.tm_min);

其他说明

为什么用 _s 版:老的 localtime/gmtime 返回指向内部静态缓冲区的指针——全程序共享一份。第二次调用会覆盖第一次的结果,多线程下更是直接竞态,拿到的字段可能是两次调用的混合体。_s 版让调用者自备缓冲,彻底消除该问题;MSVC 对旧版报 C4996 警告。POSIX 平台的等价物是 localtime_r(&timer, &result)(注意与 MSVC 的 _s 参数顺序又相反)。跨平台代码建议包一层薄封装。

禁用

不要保存 localtime() 返回的指针“稍后再用”——任何后续的 localtime/gmtime/ctime 调用都可能悄悄改写它指向的内容。

strftime

按 “%Y-%m-%d” 这类模板把分解时间渲染成字符串,是输出给人看的日期时间的标准做法。

函数原型

size_t strftime(char *buf, size_t maxsize, const char *fmt, const struct tm *tp);

参数

参数类型说明
bufchar *输出缓冲区,格式化结果连同结尾 '\0' 写在这里
maxsizesize_t缓冲区容量(含结尾 '\0' 的字节数),惯用 sizeof buf;容量不足时函数返回 0 且 buf 内容不可用
fmtconst char *含 % 转换符的模板,常用组合如 "%Y-%m-%d %H:%M:%S";非 % 字符原样复制。完整格式符见下方“其他说明”
tpconst struct tm *已拆分的时间,通常来自 localtime_s/gmtime_s;函数只读不改

返回值

成功返回写入 buf 的字符数(不含结尾 '\0');缓冲区放不下时返回 0,此时 buf 的内容不可用。易错点:0 也可能是“格式串本身就产生空串”这一合法结果,所以判断失败时要结合 fmt 是否为空一起看;标准不设置 errno,没有更细的错误详情。

示例

char buf[64];
struct tm t;
time_t now = time(NULL);
localtime_s(&t, &now);
strftime(buf, sizeof buf, "%Y-%m-%d %H:%M:%S", &t);   // 2026-08-14 09:30:00
puts(buf);

其他说明

常用格式符一览(可组合进 fmt):

格式符类型说明
%Y格式符四位年份(已替你处理 +1900),如 2026
%m格式符月份 01–12(已替你处理 +1)
%d格式符日 01–31
%H格式符小时 00–23(12 小时制用 %I 配 %p)
%M格式符分钟 00–59
%S格式符秒 00–60
%A / %a格式符星期全称 / 缩写(受 locale 影响)
%B / %b格式符月份全称 / 缩写(受 locale 影响)
%j格式符年内第几天 001–366
%p格式符AM / PM
%z / %Z格式符时区偏移(+0800)/ 时区名
%F / %T格式符%Y-%m-%d / %H:%M:%S 的简写(C99)

格式化日期的首选:用它就不必手动处理 +1900/+1,也比拼接 sprintf 安全。反向解析(字符串转 tm)标准 C 没有,POSIX 提供 strptime,Windows 上需自己 sscanf 或用 C++ 的 std::get_time。

timespec_get 现代提示

取当前时间并附带纳秒字段,比只有秒级的 time 精细得多,适合打日志时间戳和测墙钟耗时。

函数原型

struct timespec {
    time_t tv_sec;
    long tv_nsec;
};

int timespec_get(struct timespec *ts, int base);

参数

参数类型说明
tsstruct timespec *接收结果的缓冲:tv_sec 为秒(time_t)、tv_nsec 为纳秒(long,取值 [0, 999999999])
baseint时间基准。标准只定义了 TIME_UTC(自纪元起的 UTC 时间),实现可扩展其他值;C11 起可用

返回值

成功返回 base 的值(即传入 TIME_UTC 时返回 TIME_UTC,是个非零值);失败返回 0,此时 *ts 未被设置;标准不提供 errno 之类的错误详情,失败通常意味着该基准不被支持。

示例

struct timespec a, b;
timespec_get(&a, TIME_UTC);
run_task();
timespec_get(&b, TIME_UTC);
double ms = (b.tv_sec - a.tv_sec) * 1e3
          + (b.tv_nsec - a.tv_nsec) / 1e6;   // 毫秒级墙钟耗时
printf("%.2f ms\n", ms);

其他说明

time() 只有秒级精度,timespec_get(C11)把分辨率提升到纳秒字段(实际精度取决于系统,通常微秒到百纳秒级),适合给日志打时间戳、测墙钟耗时。它测的是可能被对时调整的“真实时间”,做精密基准测试仍应选单调时钟(POSIX clock_gettime(CLOCK_MONOTONIC),或 C++ 的 std::chrono::steady_clock)。

分类 8其他常用头文件

除了字符串、输入输出、内存这些"大部头"之外,C 标准库还有一批短小精悍的头文件:断言、错误码、可变参数、固定宽度整数、各类极限常量。它们代码量不大,却是写出可移植、可调试 C 程序的基础设施。本章把这些零散但高频的设施集中讲清楚。

速览

本章速览——这些不是"函数库",而是撑起 C 程序类型、诊断与可移植性的地基,写对了几乎感觉不到它们,写错了满屏诡异 bug。

assert

推荐

运行期检查程序内部不变量,条件为假就打印文件行号并 abort 终止;发布版定义 NDEBUG 后整条语句蒸发。

函数原型

#include <assert.h>

void assert(scalar expression);

参数

参数类型说明
expression标量表达式(整数、浮点、指针均可)期望恒为真的条件。assert 是宏而非真正的函数:表达式为假(等于 0)时,向 stderr 打印表达式文本、文件名、行号(以及实现可能附带的函数名),随后调用 abort() 终止程序。易错点:表达式绝不能带副作用——发布版里整条语句会被替换为 ((void)0),副作用随之消失,例如 assert(p = f())、assert(fclose(fp) == 0) 在 Release 下根本不会执行。常用技巧是与字符串字面量用 && 连写,如 assert(b != 0.0 && "除数不能为零"),让诊断信息自带人话说明

返回值

无返回值(宏展开为 void 表达式)。条件为真时什么也不做;条件为假时不会返回调用点,而是先向 stderr 输出诊断信息,再调用 abort() 使进程异常终止(通常伴随 core dump / 崩溃对话框)。错误详情不通过 errno 传递,而是直接体现在 stderr 的诊断文本与退出状态里。

示例

double safe_div(double a, double b) {    assert(b != 0.0 && "除数不能为零");// 与字符串字面量 && 连用,失败时消息更可读    return a / b;} int main(void) {    printf("%.2f\n", safe_div(6.0, 3.0));// 正常路径:断言通过,输出 2.00    return 0;}

其他说明

assert 与 NDEBUG 宏联动:若在包含 <assert.h> 之前定义了 NDEBUG(通常由发布版编译选项 -DNDEBUG / MSVC Release 配置注入),assert(x) 展开为 ((void)0),零开销消失。因此断言表达式绝不能带副作用——assert(fclose(fp) == 0) 在发布版里连文件都不会关。

现代提示

断言哲学:assert 检查的是"程序员的错"(违反内部不变量、契约、不可能到达的分支),而不是"用户的错"(非法输入、文件不存在)。后者应当用正常的错误处理路径,因为发布版里断言会整体消失。编译期能判定的条件请改用下文的 static_assert;C++ 中运行期契约还可考虑异常。

errno

库函数出错时写进去的错误码左值,读它可以问出"到底哪儿失败了",再交给 strerror/perror 翻成人话。

函数原型

#include <errno.h>

errno

参数

参数类型说明
errno宏,展开为 int 左值它不是函数也不是普通全局变量,而是展开为一个可读可写的 int 左值的宏(实现上常为 (*__errno_location()) 之类)。可以直接赋值,惯用法是调用前写 errno = 0;
ERANGE宏常量结果超出可表示范围(strtol 溢出、exp 上溢等)
EINVAL宏常量参数无效(POSIX 广泛使用;部分标准库函数也会设置)
ENOENT宏常量文件或目录不存在(fopen 失败后常见)
EDOM宏常量数学函数定义域错误,如 sqrt(-1.0)

返回值

不是函数,而是一个可修改的 int 左值。自 C11 起标准保证它是线程局部的,各线程互不干扰;主流实现(glibc、MSVC)早已如此。库函数只承诺"出错时设置 errno",从不承诺"成功时清零",所以读它之前必须先用函数自身的返回值判定"确实失败";对 strtol、数学函数这类靠 errno 区分结果的接口,必须调用前先清零、调用后再检查。取错误详情:用 strerror(errno) 转成文字,或用 perror("上下文") 直接打印到 stderr。

示例

errno = 0;// 1. 调用前清零long v = strtol(s, &end, 10);if (errno == ERANGE)// 2. 调用后检查    fprintf(stderr, "数值溢出: %s\n", s);else if (end == s)    fprintf(stderr, "不是数字: %s\n", s);// 未消费任何字符

其他说明

把错误码转成文字用 strerror(errno);MSVC 对 strerror 报 C4996 警告,可改用 strerror_s(C11 附录 K),POSIX 下线程安全版本是 strerror_r。C++ 的现代等价物是 std::error_code / std::system_error。

va_list / va_start / va_arg / va_end

让函数能吃下不定个数的参数并逐个取出:va_start 起头、va_arg 取一个、va_end 收尾、va_copy 备份游标以便二次遍历。

函数原型

#include <stdarg.h>

typedef ... va_list;

void va_start(va_list ap, parmN);
type va_arg(va_list ap, type);
void va_end(va_list ap);
void va_copy(va_list dst, va_list src);

参数

参数类型说明
apva_list参数遍历游标。va_list 是保存可变参数遍历状态的不透明类型,只能通过这几个宏操作,不要假设它是指针或数组
parmN—va_start 专用:... 之前的最后一个具名参数名(不是它的类型,也不能是寄存器变量、数组或函数类型)。遍历从它之后的第一个实参开始
type类型名va_arg 专用:期望的参数类型,必须与实参经默认实参提升后的类型一致。写 char/short/float 是未定义行为,应写 int/double
dstva_listva_copy(C99)专用:目标游标,复制 src 的当前遍历状态;dst 用完后同样需要自己的 va_end
srcva_listva_copy 专用:源游标,复制后 src 自身状态不变。需要二次遍历同一组参数时用它,而不是重复 va_start 或重用已消费的游标

返回值

va_arg 返回按 type 解释的下一个实参(每次调用使游标前进一个参数);va_start、va_end、va_copy 均无返回值。这套宏没有任何错误报告机制:参数个数与类型必须由调用者另行约定(计数参数或格式串),取多了、取错类型都是未定义行为,不会设置 errno、也不会返回失败值——错误只能靠约定与编译器的 format 属性检查来避免。va_start 与 va_end 必须在每条返回路径上配对。

示例

/* 完整示例:对 n 个 int 求和 */int sum(int n, ...) {    va_list ap;    va_start(ap, n);// 从 n 之后开始取参    int total = 0;    for (int i = 0; i < n; i++)        total += va_arg(ap, int);// 每次前进一个 int    va_end(ap);// 必须配对调用    return total;}/* 调用:sum(3, 10, 20, 30) == 60 */

其他说明

陷阱:可变参数经历默认实参提升——char/short 提升为 int,float 提升为 double,所以 va_arg(ap, char) 与 va_arg(ap, float) 是未定义行为,应写 int / double。参数个数与类型信息必须由调用者另行约定(计数参数或格式串),取多了、取错类型都是未定义行为。

现代提示

自己封装 printf 风格接口时,接受 va_list 并转发给 vsnprintf 是标准做法;若需二次遍历,用 va_copy 复制而不是重用。C++ 中优先用变参模板或 std::format,类型安全且无提升陷阱。

offsetof

在编译期算出某个成员距结构体开头有多少字节,用来看清对齐填充、做二进制序列化,以及由成员指针反推外层对象。

函数原型

#include <stddef.h>

size_t offsetof(type, member);

参数

参数类型说明
type结构体类型名如 struct Point。offsetof 是宏而非函数,接收的是类型名而不是值;只对标准布局的结构体有意义
member成员名该结构体中的成员标识符,求它相对结构体首地址的字节偏移。不能是位域成员(标准明确规定为未定义)

返回值

返回 size_t 型整数常量表达式,表示从结构体起始地址到该成员的偏移字节数(因此可用于 static_assert、数组维度等编译期场景)。没有失败取值:参数不合法(成员不存在、写成位域)属于编译错误或未定义行为,而不是运行期返回错误码,所以不涉及 errno。

示例

struct Packet { char tag; int len; char data[8]; };

size_t off = offsetof(struct Packet, len);
printf("len 位于偏移 %zu\n", off);   // 通常输出 4:tag 后有 3 字节对齐填充

其他说明

典型用途:观察对齐填充、二进制序列化,以及内核风格的 container_of——由成员指针反推外层结构体指针。自己用指针减法模拟 offsetof(如 (size_t)&((T*)0)->m)在标准层面是未定义行为,应始终使用这个宏。

size_t / ptrdiff_t / NULL

分别表示对象大小、两个指针之差和空指针:前者无符号、后者有符号,用它们而不是 int 表达长度与下标,代码才能在 32/64 位平台通吃。

函数原型

#include <stddef.h>

typedef ... size_t;
typedef ... ptrdiff_t;

#define NULL ...

参数

参数类型说明
size_t无符号整数类型sizeof 的结果类型,能表示实现所允许的任何对象大小。64 位平台通常 8 字节、32 位平台 4 字节。打印用 %zu。易错点:无符号,for (size_t i = n - 1; i >= 0; i--) 条件恒真,是死循环
ptrdiff_t有符号整数类型两个指针相减的结果类型,可以为负。宽度与 size_t 相同(64 位平台 8 字节、32 位 4 字节)。打印用 %td
NULL宏空指针常量,依实现展开为 0、0L 或 ((void*)0)。正因为它可能只是整数 0,在 C++ 的重载决议中会产生歧义

返回值

均为类型/宏定义,无运行期行为,也就无所谓成功与失败、不涉及 errno。它们的价值在于可移植性:64 位平台上 size_t/ptrdiff_t 通常为 8 字节,32 位平台为 4 字节——所以它们比 int/unsigned 更适合表达"大小"与"下标"。

示例

int a[100];size_t n = sizeof a / sizeof a[0];// 元素个数用 size_tptrdiff_t d = &a[70] - &a[20];// 指针差用 ptrdiff_t,可以为负printf("n=%zu d=%td\n", n, d);// 专用格式:%zu 与 %td

其他说明

陷阱:size_t 是无符号的,for (size_t i = n - 1; i >= 0; i--) 是死循环(条件恒真);倒序遍历应写 for (size_t i = n; i-- > 0; )。混合有符号/无符号比较会触发隐式转换,建议开启 -Wconversion 类警告。

现代提示

C23 引入了关键字 nullptr 与类型 nullptr_t,与 C++11 对齐;在旧标准里,C 惯用 NULL,而现代 C++ 一律用 nullptr(NULL 在 C++ 中可能只是整数 0,重载决议时有歧义)。

查各种类型到底能装多大、精度到哪一位的编译期常量,用来在溢出发生前拦住它,并给浮点比较定一个靠谱的容差。

static_assert

现代提示

在编译期校验一个常量条件,不满足就直接编译报错,常用来锁死结构体大小、字节位数等 ABI 与平台假设。

函数原型

#include <assert.h>

static_assert(constant-expression, "message");
static_assert(constant-expression);

参数

参数类型说明
constant-expression整型常量表达式必须在编译期可求值(如 sizeof、offsetof、枚举值的算术);为 0 时直接编译失败
message字符串字面量出现在编译错误信息中,用来说明违反了什么假设;C23(以及 C++17)起可省略,即只写一个参数的形式
<assert.h>头文件C11 在此提供 static_assert 宏(映射到关键字 _Static_assert);C23 与 C++11 起 static_assert 本身就是关键字,不需要包含任何头文件

返回值

无返回值,它是一条声明而不是表达式。断言失败发生在编译期,以编译错误(并打印 message)的形式报告,程序根本不会生成;成功时不产生任何运行期代码,也不受 NDEBUG 影响——这是它与 assert 的本质区别,也意味着它与 errno 毫无关系。

示例

其他说明

典型用途:锁定结构体大小与偏移(常与 offsetof 配合)、校验平台假设、检查数组长度与枚举个数同步。C11 的原生拼写是 _Static_assert,C23 与 C++11 起 static_assert 本身就是关键字,无需包含任何头文件。凡是编译期能验证的条件,都应从运行期 assert 前移到 static_assert——错误暴露得越早越便宜。
